# Android example

A real Android app (`MainActivity`) that calls a C library through JNI bindings generated by the
plugin. Both plugins are applied to this single module:

- **konan plugin** → cross-compiles `native/*.c` to `libmymath.a` per ABI, generates the JNI `.c`
  stubs + runtime-free Kotlin bridges, and links a self-contained `libexamplestubs.so` per ABI.
- **AGP** (9.x, with built-in Kotlin) → compiles the app and packages the `.so` into the APK.

## Prerequisites

- A Kotlin/Native distribution (auto-detected, or `KONAN_HOME`).
- Android SDK (`local.properties` → `sdk.dir`); the example targets `compileSdk 36`, `minSdk 21`.
- The plugin published to mavenLocal:
  ```bash
  (cd ../.. && ./gradlew publishToMavenLocal)
  ```
- This module uses its own Gradle wrapper (9.4.1, required by AGP 9).

## Build

```bash
./gradlew assembleDebug
```

This runs the full chain and produces `build/outputs/apk/debug/android-example-debug.apk` containing:

```
lib/arm64-v8a/libexamplestubs.so
lib/x86_64/libexamplestubs.so      # emulator
classes*.dex                       # MainActivity + generated example.kt bridges
```

## Run on a device / emulator

```bash
./gradlew installDebug      # deploy to a connected device/emulator
# then launch "JNI Example" from the launcher
```

The screen shows:
```
JNI from Kotlin/Native cinterop:
my_add(2, 3)  = 5
my_scale(4.0) = 40.0
```

## How it's wired (`build.gradle.kts`)

Just two config blocks — the plugin does the wiring:

- `konanConfig { targets = [android_arm64, android_x64] }` → the `.a`s.
- `jvmInterop { headers = ["mymath.h"]; packageName = "example"; ... }` → bridges + `.so`s.

When AGP is present the plugin **automatically** adds the generated Kotlin bridges as a source
directory and the per-ABI `jniLibs/` as native libraries (via the AGP variant API), and orders
`generateJvmInterop` / `linkJvmInterop` / `runKonanClang` ahead of the build. No `sourceSets` or
`dependsOn` boilerplate needed.

`MainActivity` calls `example.add/scale` (in `src/main/kotlin/example/Api.kt`), which call the
generated `kniBridgeN`. `System.loadLibrary("examplestubs")` loads the `.so` from the APK — no
`java.library.path` on Android.

The `.so` gets `jni.h` from the NDK sysroot; the bridges are runtime-free (no `kotlinx.cinterop`), so
nothing extra ships in the APK.
